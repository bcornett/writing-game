# Dot's Writing Quest — working notes

A letters-and-numbers PWA for Maddie's iPad: trace, write, spot the backwards
one, b-or-d, pop the flipped bubbles, quest, stickers. Personal project
(Cornett Ventures side, not Paystar). Read `README.md` first, then this.

Built on the framework in `~/Projects/flying-game/FRAMEWORK.md` — the platform
half (serving, https, offline cache, updates, icons, QR) is that code, adapted.
The game half is all new.

## Ground rules

- **No build step, no dependencies, no image assets.** ES modules straight
  off disk. Icons, sounds, confetti and the mascot are drawn in code. The one
  asset set is `audio/voice/*.mp3`, generated by `npm run voices`.
- **Keep `src/core/` pure.** No `document`, no `window`. That boundary is what
  makes the tracer, the grader and the quest planner testable in Node, and
  every test that matters depends on it.
- **Regenerate `sw.js` after changing any shipped file.** `npm run sw`, and
  commit it. `tests/sw.test.js` fails if it drifts. The dev server generates
  it live, so you only notice in a static deploy — which is exactly when it
  matters.
- **Regenerate voice clips after changing any line in `phrases.js` or
  `glyphs.js`.** `npm run voices` only sends what changed (hash per clip);
  `tests/phrases.test.js` fails if the manifest drifts. The API key lives in
  `.env` (gitignored) — never in chat, never in code.
- **It has to stay unloseable.** No fail state, no timer, no score that goes
  down. Mistakes are a wobble and a hint. A reversal is a specific tip and a
  chance to trace with Dot, never a "wrong".
- **Copy is short, warm, lowercase-friendly.** The listener is five. Letter
  names in spoken text are spelled as sounds ("little bee") — see glyphs.js.

## Where things live

- A glyph's strokes, spoken name, rhyme, flip hint → `src/core/glyphs.js`.
  Strokes are absolute SVG paths in a 100×100 box on the handwriting lines
  (top 12, middle 48, base 84, descender 98), in the order and direction a
  kindergarten teacher models. Stroke order matters: it is what the tracer
  enforces and what fixes a reversal.
- Which glyphs are reversal-prone, the twin pairs, the default focus set →
  `src/core/curriculum.js` and `DEFAULT_FOCUS` in `progress.js`.
- Grading thresholds → `GRADE` in `src/core/grader.js`. Pinned by
  `tests/grader.test.js`; `npm run sweep` prints the per-glyph picture.
- Tracing tolerances → `TRACE` in `src/core/tracer.js`.
- Mastery weights, star/sticker maths → `src/core/progress.js`.
- Everything Dot says → `src/core/phrases.js` (+ per-glyph lines in glyphs.js).
- Screens → `src/ui/screens/*.js`, each `mount(root, app, params) → cleanup`.
  The shared `app` object is built in `src/main.js`.
- Looks → `style.css`. Sections are commented; responsive rules at the end.

## Conventions worth knowing

**Twins are computed, not listed.** `distinctTransforms(glyph)` decides which
of mirror / flip / rot look different from the glyph by grading the transform
against the original. A 0 has no twins; a b has all three. `eligibleForSpot`
follows from it, so a focus set of only symmetric glyphs can't make a spot or
pop round (the quest planner copes).

**Grading is sequence-aware on purpose.** The point-cloud metrics were tried
first and could not tell a c from its mirror (their ink overlaps almost
everywhere). Dynamic time warping over every stroke order and direction can.
Closed loops (o, 0, 8) may start anywhere along the loop. Coverage catches
missing or extra parts that warping forgives.

**Voice playback can never hang a caller.** `voice.say()` settles when a line
finishes, is interrupted, or times out. Screens `await` it freely.

**Screens under a quest are the same screens.** They get a `quest.onDone`
callback instead of showing their own finish card; the quest screen mounts
them itself and inserts a trace + rewrite after a 0-star write.

## Verifying

`npm test` covers the logic. For anything visual, run it and look:

```bash
npm start
```

Synthetic fingers work in the browser console — dispatch `PointerEvent`s on
`.trace-svg` / `.write-svg` in viewBox coordinates (see the dev notes in
BACKLOG.md). Things the tests can't see and that were caught only on screen:
round caps drawing a stray dot at a zero-length dash, an SVG transform-origin
defaulting to the viewport, a sticker overlay replacing the result card.

## Audience

The player is a small child. Nothing tappable under 56px. Every action is
rewarded with a sound, a face, or a star.
